# AI Agent Rules for Memora

These rules capture the constraints for the AI Hackathon 2026 Sri Lanka project. They apply to every AI coding agent working in this repository.

## Competition constraints

- Build one project only: Memora.
- All coding work must happen during the official hacking hours on Saturday, 17 October 2026. Brainstorming before the event is allowed, but agents must not introduce pre-written implementation work as if it were created during the hacking period.
- Keep the project meaningfully Jac-based. At least 80% of the code submitted to the competition must be Jac.
- Use Jac and Jaseci features where they provide genuine value. Do not add superficial Jac code solely to satisfy the percentage requirement.
- Preserve a clear record of material work and decisions so the team can accurately describe how Jac and Jaseci were used.
- Do not misrepresent authorship, timing, dependencies, capabilities, test results, or demo behavior. Misrepresentation can disqualify the project.

## Agent behavior

- Before implementing a feature, confirm that it supports the hackathon project and does not create a second project or unrelated prototype.
- Prefer Jac-native solutions for application logic, agents, data, backend, and frontend whenever practical.
- Keep non-Jac code minimal and purposeful. If non-Jac code is added, document why it is needed and where it is used.
- Do not silently copy substantial code, generate hidden pre-event work, or claim that an unavailable integration works.
- Do not add secrets, API keys, credentials, or private personal information to the repository.
- Never push to `main` without strict, explicit confirmation from the user immediately before the push. This includes force-pushes and any equivalent command that updates the remote `main` branch.
- Run relevant checks and tests before reporting completion. Report failures and unverified behavior plainly.
- Keep the repository demo-ready: simple startup instructions, a reliable entry point, and a focused user flow take priority over speculative features.

## Submission readiness

The final project should support the competition submission checklist:

- A working GitHub repository link.
- A working project and demo video submitted by 5:30 PM on 17 October 2026.
- A pitch deck describing the problem, solution, impact, and novelty.
- A written description explaining how Jac and Jaseci tools were used.
- The official Jac repository starred: https://github.com/jaseci-labs/jac
- Optional hosting on Jac Hammer: https://jachammer.ai/

## Quality priorities

Optimize implementation and review for the published judging criteria, in this order of practical importance:

1. Technical execution and reliable functionality.
2. Excellent, genuine use of Jac and Jaseci.
3. Creativity and innovation.
4. Depth of agentic behavior.
5. Impact and novelty.
6. A clear presentation and demo video.

## Team and submission rules

- The competition permits teams of three people; do not assume additional team members or submit multiple projects for the team.
- Every team member must register and check in on the event day.
- Submit through the shared submission link before the deadline. Late entries cannot win.
- Build and communicate in good faith, and treat collaborators and organizers respectfully.
